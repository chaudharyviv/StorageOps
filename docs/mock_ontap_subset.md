# Mock ONTAP API: served subset

The mock follows the NetApp ONTAP **9.19.1** REST API reference (read 2026-11-09). It serves read-only GET requests over a simulator metrics file, using only field names that appear in the reference pages below. All data is synthetic.

This file is generated by `python -m simulator.mock_ontap_api.subset_doc`; do not edit it by hand. A test fails if it drifts from the code.

## Behaviour

- **Read-only.** Only GET is served. POST, PUT, PATCH and DELETE return 405 in ONTAP's `{"error": {"code", "message"}}` envelope.
- **Replay time.** The `MOCK_NOW` environment variable (ISO-8601, UTC if no zone) sets the replay time, and `?mock_now=` overrides it per request. Responses show the latest sample at or before that time; with neither set, the last sample in the file. A time before the first sample returns 404. `mock_now` is not an ONTAP parameter.
- **`fields`.** Supported as in the reference: a comma-separated or repeated list of paths, `*` for the default fields, `**` for everything. Properties the reference lists as expensive are returned only when requested; they are marked below.
- **Shape.** Collections return `_links`, `num_records` and `records`. `GET /api/cluster` returns a single object, as the reference documents. Per-record `_links` are left out because the instance endpoints they would point to are not served.
- **Not supported.** Every other ONTAP query parameter (filters, `max_records`, `return_records`, `order_by`, ...) is ignored.
- **Labels.** The mock opens the metrics file only; it never opens the labels file.

## Type and unit conversions

Where a documented field's type or unit differs from the simulator metric behind it, the mock converts. These conversions are tested.

| Field | Simulator metric | Simulator unit | Documented type | Conversion | Evidence on the reference page |
| --- | --- | --- | --- | --- | --- |
| snapmirror: lag_time | `lag_seconds` | seconds | string | whole seconds as an ISO-8601 duration, e.g. 120 -> PT2M, 93784 -> P1DT2H3M4S | type and description only; the format comes from examples (PT8H35M42S, P2DT, PT10H) |
| snapmirror: healthy | `transfer_errors` | count | boolean | false when the error count is above 0, otherwise true | type and description only ("Is the relationship healthy?") |
| all byte fields | `*_bytes` | bytes | integer | float rounded to a whole number of bytes | descriptions say "in bytes" |
| all percent fields | `*_percent` | percent | integer | float rounded to a whole percent | descriptions say "as a percent" or "percentage" |
| volumes: efficiency.ratio | `efficiency.ratio` | ratio | number | float rounded to 2 decimals | documented as number |
| volumes: metric.iops.total | `iops` | iops | integer | float rounded to a whole number | documented as integer |
| volumes: metric.timestamp | `(sample time)` | UTC time | string | formatted as YYYY-MM-DD HH:MM:SS +0000 | examples only ("2017-01-25 11:20:13 +0000") |

Not served, but would need a unit conversion if it were:

- `latency.read_p95_ms`: simulator ms; the reference says latency is in microseconds
- `latency.write_p95_ms`: simulator ms; the reference says latency is in microseconds
- `throughput_mbps`: simulator MB/s; the reference says throughput is bytes per second

| `data.entropy_proxy` | No documented volume field; entropy appears only inside anti-ransomware peak statistics. |

## Unclear points in the reference

- `metric.duration` is documented as an ISO-8601 duration with a list of allowed values, but the list is absent from the page text; only `PT15S` appears, in an example. The mock omits `metric.duration` rather than state a sampling window it cannot honour (simulator samples are one minute apart).
- `space.used` is described as virtual space "before storage efficiency", while `space.physical_used` is the physical figure. The simulator has one used figure, after efficiency, so both are served from `space.used_bytes`.
- `state` for aggregates is a plain string with no listed values, so it is not served. Volume `state` is served as `online`, a value named in the volume `state` description.
- The reference documents no per-object metrics endpoints on these pages; performance numbers appear as the embedded `metric` object (volumes, aggregates, cluster). Separate metrics endpoints were not checked and are not served.
